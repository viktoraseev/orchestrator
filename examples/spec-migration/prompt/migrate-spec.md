Ты выполняешь очередную итерацию переноса продуктовых требований orchestrator из временных Markdown-спецификаций в исполняемые `features/*.feature`.

Сначала прочитай `AGENTS.md` и соблюдай его полностью. Работай только в текущем репозитории и сохраняй все чужие изменения.

Разбери `ORC_INPUT` как YAML sequence, а не как поиск literal составного имени. Artifact `decision:fix` представлен элементом с двумя отдельными полями `step-id: decision` и `input-id: fix`; строки `decision:fix` в mapping нет. Если пара этих полей есть, прочитай файл из поля `path`: он содержит замечания предыдущего review. Исправь только эти замечания текущей незакоммиченной пачки, продолжай использовать уже созданный для неё тикет и не выбирай новую пачку.

Только если `ORC_INPUT` равен пустой sequence `[]` для bootstrap либо содержит пару полей `step-id: decision` и `input-id: repeat`, выбери следующую крупную связную пачку нормативных требований, которая всё ещё остаётся в `cli.md` или другом временном документе-источнике. Сначала докажи для каждого переносимого правила наличие полноценного исполняемого acceptance-сценария либо добавь или усили его, затем удали только ставший дублирующим текст документа и его source tags. Не удаляй сценарии и не подменяй потерю acceptance-покрытия unit-тестами. Создай локальный тикет через `tk`, переведи его в `in_progress` и веди в нём границы пачки. При любом другом mapping не начинай новую пачку: завершись с ошибкой и точной диагностикой.

Если нормативных требований для переноса больше не осталось, не меняй репозиторий. Создай временный regular file с кратким обоснованием завершения и выполни `"$PWD/target/release/orchestrator" attempt complete --artifact done <absolute-path>`. После успешного tool call заверши Agent process с кодом 0.

Для выбранной пачки используй Gherkin skill при изменении `.feature`; при изменении Rust используй `rust-skills`. Выполни релевантные targeted-проверки, затем обязательные `./scripts/test.sh` и `./scripts/build.sh`. Проверь `git diff --check` и самостоятельно сопоставь каждое удалённое нормативное правило с сохраняющим его сценарием.

Подготовь временный regular file для ревью. Укажи в нём ID тикета, точный список перенесённых требований, соответствующие Rule/Scenario, удалённые фрагменты документа, изменённые тесты и результаты проверок. Затем выполни `"$PWD/target/release/orchestrator" attempt complete --artifact review <absolute-path>`. После успешного tool call заверши Agent process с кодом 0.
