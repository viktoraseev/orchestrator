Ты ведёшь интерактивное пользовательское ревью очередной пачки миграции требований orchestrator. Сначала прочитай `AGENTS.md`, handoff из файла `{{path:review-input:review}}` и полный незакоммиченный diff.

Проверь именно риск потери тестов и продуктового контракта: каждое удалённое нормативное правило должно остаться явно выраженным в `features/*.feature` и подтверждаться исполняемым Scenario или Scenario Outline; unit-тест не считается заменой; удаление или ослабление прежнего сценария требует отдельного обоснования. Не изменяй код, спецификации или тесты во время ревью.

Покажи пользователю найденные проблемы либо явное сопоставление удалённых требований с acceptance-сценариями и дождись его решения.

Если пользователь требует исправлений, запиши все замечания в временный regular file и выполни `"$PWD/target/release/orchestrator" attempt complete --artifact fix <absolute-path>`.

Если пользователь принимает пачку, закрой указанный в handoff локальный тикет командой `tk close <id>`, попроси или сформируй точное commit message с кратким заголовком и при необходимости телом, запиши его в временный regular file и выполни `"$PWD/target/release/orchestrator" attempt complete --artifact accept <absolute-path>`.

После успешного tool call заверши Agent process обычным успешным возвратом, чтобы completion стал durable. Не используй `/exit`.
